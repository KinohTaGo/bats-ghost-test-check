# bats-ghost-test-check（日本語版）

> English version: [README.md](README.md)

[bats-core](https://github.com/bats-core/bats-core) のテストスイートで発生する
**「幽霊テスト」** を検出するツールです。幽霊テストとは、宣言され、テスト件数にも数えられ、
それでいて **一度も実行されていない** テストのことです。

---

## 1. きっかけ

あるプロジェクトのシェルスクリプト用テストを実行したところ、こう表示されました。

```
$ bats tests/
1..889
ok 1 ...
...
# bats warning: Executed 804 instead of expected 889 tests
```

**889 個あるはずのテストのうち、804 個しか動いていませんでした。85 個が実行されていません。**

しかも、動いていた 804 個はすべて `ok`（成功）でした。画面を眺めているかぎり、
異常を示すものは何もありません。テストは「全部通った」ように見えます。

テストとは、壊れていないことを確かめるための仕組みです。その仕組みが、
**確かめていないのに「確かめました」と報告していた** ことになります。

いつからこの状態だったのかは、分かりませんでした。

---

## 2. 原因

bats の内部（`libexec/bats-core/bats-preprocess`）に、テスト名を内部的な関数名へ変換する
処理があります。その処理は、次の条件式で2つの方式を切り替えています。

```sh
if [[ ! "$name" =~ [^[:alnum:]\ _-] ]]; then
```

`[:alnum:]` は「英数字」を表す指定です。**ところがこの判定は、パソコンの言語設定
（ロケール）によって意味が変わります。**

| 言語設定 | `[:alnum:]` が漢字・キリル文字を | 結果 |
|---|---|---|
| `LC_ALL=C` | 英数字とみなさない | 安全な方式（16進数へ変換）が選ばれる → 正常 |
| `LC_ALL=en_US.UTF-8` | **英数字とみなす** | 「変換不要」と判断され、日本語がそのまま関数名に埋め込まれる |

後者の場合、一部のテストは実行時に関数が見つからず、**そのまま消えます。**

同じ bats、同じテストファイル、同じ bash です。**違うのは言語設定だけ** です。

| 設定 | 宣言数 | 実行数 | 幽霊 | 終了コード |
|---|---|---|---|---|
| `LC_ALL=C` | 21 | 21 | 0 | 0 |
| `LC_ALL=en_US.UTF-8` | 21 | 16 | **5** | 1 |

---

## 3. 分からなかったこと（正直に書きます）

ここから先は、**最後まで解明できませんでした。**

UTF-8 環境では、上記の日本語名はすべて「変換不要」の分岐に落ちます。ところが、
実際に消えるのはその一部だけでした。

| テスト名 | コードポイント | 結果 |
|---|---|---|
| `件` | U+4EF6 | **動く** |
| `中` | U+4E2D | 消える |
| `亜` | U+4E9C | 消える |
| `あ` | U+3042 | 消える |
| `Кириллица` | U+041A… | 消える |
| `é` | U+00E9 | **動く** |
| `Ａ` | U+FF21 | **動く** |

`件` と `中` はどちらも同じ漢字の領域にある文字です。それでも結果が違います。

つまり **境界は「文字の種類」でも「文字数」でもなく、文字ひとつひとつ（コードポイント）
単位** ということになります。以下はすべて実験で否定しました。

- マルチバイト文字の個数によるものか → **違う**（1文字で消えるものも、3文字で生き残るものもある）
- 文字の種類（漢字・キリル文字など）によるものか → **違う**（同じ漢字で結果が割れる）
- ASCII 文字と混ざっているかどうか → **違う**

また、bash 自体には問題がないことも確認しました。`test_あ` や `test_中` といった関数名は、
同じシェル上で**定義も呼び出しも問題なくできます。** したがって「bash の制約」という
説明は成り立ちません。

**推測で埋めるのはやめて、「特定できなかった」とそのまま報告することにしました。**

### なぜ未解明でも報告できるのか

修正案が、この未解明部分に依存しないからです。

```diff
-  if [[ ! "$name" =~ [^[:alnum:]\ _-] ]]; then
+  if [[ ! "$name" =~ [^a-zA-Z0-9\ _-] ]]; then
```

そもそも「変換不要」の分岐は、**そのままシェルの識別子として使える名前**のための
最適化です。非 ASCII 文字はその条件を満たしません。ですから、
**どの文字がたまたま生き残るかに関わらず**、非 ASCII は変換する側へ回すべきです。

なお、`LC_ALL=C` で囲む修正案もありますが、そちらは推奨しませんでした。
周囲の環境変数に依存し続けるからです。ASCII の範囲を明示する方が、
**「シェル識別子として安全な文字」という意図がコードから読み取れます。**

---

## 4. bats 自身の警告では足りない理由

bats は `# bats warning: Executed N instead of expected M tests` という警告を出し、
終了コードも 0 以外になります。つまり **完全に無音というわけではありません。**

にもかかわらず、実際には見落とされます。

- 標準エラー出力へのコメント行なので、整形ツールを挟むと消えます
- `bats tests/ | tail -40` とすると、末尾だけが表示され、**終了コードも `tail` のもの** になります
- CI が「`not ok` が無いこと」を条件にしていると、素通りします。**幽霊テストは行そのものを出さない**からです

幽霊テストとは、**存在しないことによって合格するテスト**です。専用の検査を用意する価値があります。

---

## 5. 2つの検査

### 静的検査 — `bats-nonascii-name-check.py`

`.bats` ファイルを読み、テスト名に非 ASCII 文字が含まれていないかを調べるだけです。
bats を起動しないので高速で、**言語設定に一切依存しません。**

```
tests/unit/test_sync.bats:42: non-ASCII @test name: "同期が7件で成功する"
    U+540C '同' CJK UNIFIED IDEOGRAPH-540C
```

**CI に組み込むならこちらです。**

### 動的検査 — `bats-declared-vs-executed.sh`

実際にテストを走らせ、宣言数と実行数をファイル単位で比較します。
差があれば、**消えたテストの名前を名指しします。**

```
tests/unit/test_sync.bats: declared=12 executed=10 shortfall=2
  ghost: 同期が7件で成功する
```

ファイルごとに bats を再実行するため遅いですが、非 ASCII 以外の原因による
消失も捕まえられます。

---

## 6. 落とし穴 — 動的検査は「バグ自身の発火条件」を引き継ぎます

幽霊化は UTF-8 環境でしか起きません。そして動的検査は bats を実行するので、
**その環境の言語設定をそのまま引き継ぎます。**

つまり **CI サーバーの言語設定が未設定（`C` 相当）だと、開発者の手元では壊れている
スイートを「問題なし」と報告します。**

これは実際に起きました。あるプロジェクトが動的検査を git の push 前フックに組み込んだのですが、
そのフックが引き継ぐ環境が `LC_CTYPE=C` だったため、**幽霊化するように作った検証用ファイルに
対して「差分ゼロ」を返していました。**

**バグの発火条件と、検知器の発火条件が、同じ変数だったのです。**

動的検査を使う場合は、言語設定を明示してください。

```sh
LC_ALL=en_US.UTF-8 ./bats-declared-vs-executed.sh tests/
```

静的検査にはこの依存がありません。

## 7. 開発中に自分が踏んだ失敗

動的検査を作ったとき、**私自身が同種のバグを混入させました。**

消えたテスト名を特定するために、宣言された名前の一覧と実行された名前の一覧を
`comm` コマンドで比較していました。ところが `comm` は、**両方の入力が同じ順序で
並んでいることを前提とします。**

そして `sort` の並び順は、**言語設定によって変わります。** UTF-8 環境では
マルチバイト文字の並びがバイト順と一致しないため、比較結果が壊れました。

結果、実際には動いていた `件` を「消えた」と報告し、本当に消えていた `あ` を
見落としていました。

**言語設定に起因するバグを検出するツールが、言語設定に起因するバグを踏んでいた** わけです。

`LC_ALL=C sort` に修正済みです。この経緯はコード内のコメントとして残しました。
同じ罠を踏む人への注意になると考えたためです。

---

## 8. 推奨する運用

**テスト名は ASCII で書いてください。** 日本語の説明はテスト本体のコメントに置きます。

```bash
@test "sync succeeds with 7 records" {
  # 同期が7件で成功すること
  ...
}
```

これは好みの問題ではありません。**どの文字が安全かを判定する根拠が存在しない**以上、
個別に「これは大丈夫」と判断することができないからです。

## 9. 導入

どちらも単体で動きます（Python 3.8 以降 / bash）。依存パッケージはありません。

```sh
git clone https://github.com/KinohTaGo/bats-ghost-test-check
cp bats-ghost-test-check/bin/* /usr/local/bin/
```
